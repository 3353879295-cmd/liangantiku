## 1. 目标

把小程序的题库读取方式从“题目随小程序安装包发布”改为“从微信云开发在线读取”，同时保留现有题库生产纪律：

- `data/questions/*.jsonl` 仍是题目的唯一真源。
- 题目必须先通过本地 Python 校验、构建和小程序测试，才允许上传云端。
- 云端发布采用不可变版本；新版本完整核对后才能成为正式版本。
- 云端保留当前正式版和上一个正式版，出现问题时可以快速回滚。
- 第一阶段的答题进度、错题、收藏、学习设置和主题仍保存在微信本地存储。
- 小程序采用纯在线题库，不把题库写入微信本地持久化缓存。

当前本地构建报告包含 546 道 `verified` 题目。这个数量只作为首次迁移时的核对基线，不能写死在业务代码中。

## 2. 非目标

- 不建设题库编辑后台。
- 不允许在云数据库中直接修改题目来绕过 JSONL 真源。
- 不同步用户学习进度到云端。
- 不做离线题库或持久化题库缓存。
- 不索取、保存或显示微信小程序 AppSecret。
- 不在代码或版本库中保存腾讯云固定密钥、临时令牌或个人身份标识。
- 不在本次工作中修改付费套餐、自动续费、超额按量付费或其他计费设置。

## 3. 选定方案

采用成熟内容型小程序常用的“客户端 → 云函数 → 云数据库”结构。

```text
小程序页面
   ↓
QuestionRepository
   ↓
CloudQuestionRepository
   ↓
questionBank 云函数
   ↓
question_bank_config / question_bank_releases / question_bank_questions
```

不让小程序直接读取云数据库。三个集合对客户端均设为“无权限”，只有云函数使用服务端权限读取。这样可以把版本选择、参数校验、分页和错误处理集中在一个可信边界中。

未采用的方案：

- 客户端直接读数据库：代码较少，但权限、分页和版本切换会散落在客户端。
- 每个等级保存成一个大文档：当前题量可用，但题库扩大后单题读取和筛选不灵活。
- 云存储保存 JSON 文件：不符合“题库放在微信云数据库”的既定要求。

## 4. 云端数据模型

### 4.1 `question_bank_config`

只保存一个 `_id = "active"` 的配置文档：

| 字段 | 含义 |
| --- | --- |
| `_id` | 固定为 `active` |
| `schema_version` | 配置结构版本，第一版为 `1` |
| `active_release_id` | 当前正式题库版本 ID |
| `previous_release_id` | 上一个正式题库版本 ID；首次发布时为空字符串 |
| `updated_at` | 最近一次切换时间，云端时间 |

切换正式题库只更新这一份小文档。题目上传过程中不修改它，因此半成品版本不会被用户看到。

### 4.2 `question_bank_releases`

每次发布一条版本记录：

| 字段 | 含义 |
| --- | --- |
| `_id` | 发布 ID，格式为 `qb-YYYYMMDDTHHMMSSZ-<12位摘要>` |
| `status` | `staging`、`active`、`previous`、`failed` 或 `retired` |
| `schema_version` | 云题目结构版本，第一版为 `1` |
| `source_digest` | JSONL、来源、分类和知识目录的综合 SHA-256 |
| `catalog_digest` | `data/knowledge_catalog.json` 的 SHA-256 |
| `question_count` | 本版本总题数 |
| `shard_counts` | 六个职业等级分片的题数 |
| `validation_warnings` | 本地构建警告数量 |
| `created_at` | 上传开始时间 |
| `activated_at` | 正式启用时间；未启用时为空 |
| `note` | 简短发布说明，不含秘密或个人信息 |

版本记录用于核对和审计，不参与题目正文查询。

### 4.3 `question_bank_questions`

每道题是一条文档。`_id` 使用“发布 ID + 原题目 ID”的组合，确保同一道题可以同时存在于当前版和上一版中。

除现有运行时题目字段外，增加：

| 字段 | 含义 |
| --- | --- |
| `_id` | `<release_id>__<question_id>` |
| `release_id` | 所属云题库版本 |
| `question_id` | JSONL 中稳定的题目 ID |

题目正文继续使用发布产物中的 `snake_case` 字段。小程序 Repository 是转换为 `camelCase` 领域对象的唯一边界。

计划建立以下查询索引：

- `release_id + occupation + level`
- `release_id + chapter_id`
- `release_id + section_id`
- `release_id + question_id`

索引只服务现有练习、章节、模拟题、错题和收藏读取，不增加全文搜索等本阶段不需要的能力。

## 5. 云函数接口

只部署一个只读云函数 `questionBank`。它不提供创建、更新、删除或发布操作。

### 5.1 `manifest`

请求：

```json
{ "action": "manifest" }
```

返回当前正式版 ID、结构版本、题量和目录摘要。小程序首次需要题库时调用一次，并在本次运行内固定该版本 ID。

### 5.2 `list`

请求包含 `releaseId` 和筛选条件。正常页面必须至少传入职业和等级；可继续传模块、章节或小节。云函数不接受任意数据库条件表达式。

云函数按固定上限分批查询数据库，在服务端完成分页，并只返回匹配题目。响应同时返回实际使用的 `releaseId`，便于客户端检查一致性。

### 5.3 `getByIds`

请求包含 `releaseId` 和题目 ID 数组，供错题、收藏、答题恢复、题目列表和实操关联题使用。每次最多接受 100 个 ID；云函数会去重并保持请求顺序，客户端 Repository 在超过 100 个时自动分批。

### 5.4 通用响应

成功：

```json
{
  "ok": true,
  "releaseId": "...",
  "data": {}
}
```

失败：

```json
{
  "ok": false,
  "code": "QUESTION_BANK_UNAVAILABLE",
  "message": "题库暂时无法加载，请稍后重试"
}
```

返回给用户的消息使用易懂中文；数据库错误、堆栈、环境信息和内部字段不返回到小程序界面。云函数日志只记录错误码、请求类型、版本 ID 和请求追踪信息，不记录用户答案、OpenID 或其他个人标识。

业务错误码固定为 `INVALID_REQUEST`、`RELEASE_NOT_FOUND`、`INCOMPATIBLE_SCHEMA` 和 `QUESTION_BANK_UNAVAILABLE`；页面只依赖这些稳定错误码，不解析云平台原始错误文字。

## 6. 小程序读取行为

`app.ts` 使用明确的环境 ID 初始化 `wx.cloud`。`appServices.questions` 从 `LocalQuestionRepository` 切换为 `CloudQuestionRepository`，页面继续依赖同一个 `QuestionRepository` 接口。

`CloudQuestionRepository` 的责任：

- 首次调用时获取并在内存中保存当前 `releaseId`。
- 调用 `list` 和 `getByIds` 云函数动作；`getById` 复用只传一个 ID 的 `getByIds`。
- 校验云函数响应和题目字段，再映射为现有 `Question`。
- 在同一轮小程序运行期间固定版本。
- 不调用 `wx.setStorage` 保存题库、版本题目或响应正文。

本地学习数据继续只保存稳定题目 ID。应用更新到新云版本后，如果旧错题或收藏 ID 已不存在，则跳过缺失题目并显示简短提示，不清除其余本地学习数据。

知识目录第一阶段继续随小程序包发布。发布元数据保存 `catalog_digest`；如果知识目录结构发生变化，云发布门禁必须停止并要求同时发布新版小程序，避免旧客户端无法展示新目录。

## 7. 加载与错误处理

- 首页、题库、章节、模拟题、练习页在等待云题库时显示明确加载状态。
- 网络不可用、云函数失败或返回非法数据时，显示“题库加载失败，请检查网络后重试”。
- 提供“重新加载”，不自动无限重试。
- 纯在线模式下不回退到打包题库，也不把上次响应写入持久化缓存。
- 单次运行中的内存数据可以复用，页面来回切换不重复请求完全相同的数据；退出小程序后不保留。
- 进入答题页前必须获得完整题目列表，避免答题中途才发现后续题目加载失败。
- 当前版临时不可用但上一版仍在时，不由客户端自行猜测回退；管理员通过正式版本指针完成回滚，保证所有用户看到一致版本。

## 8. 本地发布流水线

### 8.1 强制门禁

每次发布必须从仓库根目录依次执行：

1. Python 单元测试。
2. `grain_quiz.cli validate`。
3. 可选的近似重复检查。
4. `grain_quiz.cli build`。
5. 云发布产物生成与摘要计算。
6. 小程序类型检查、代码检查、格式检查和 Vitest。

任一步失败都不产生可上传的正式发布包，也不改变云端正式版本。

### 8.2 云发布产物

新增生成步骤把 `dist/json` 六个分片转换为：

```text
dist/cloud/<release_id>/
├── questions.jsonl
├── release.json
└── verification.json
```

`questions.jsonl` 每行一个完整数据库文档，使用 `Insert` 导入模式。`release.json` 是版本记录，`verification.json` 保存本地预期题数、各分片题数和摘要。

### 8.3 首次发布和后续发布

1. 取得明确的云资源创建确认。
2. 创建三个集合、索引和客户端“无权限”规则。
3. 部署只读 `questionBank` 云函数。
4. 把新版本记录为 `staging`。
5. 导入 `questions.jsonl`。
6. 从云端读取并核对总题数、六个分片题数和随机样本。
7. 通过云函数执行开发者工具内的读取冒烟测试。
8. 把新版本标为 `active`，原正式版标为 `previous`。
9. 最后把 `question_bank_config/active` 指向新版本；这一步是用户可见的正式切换点。
10. 再次进行小程序首页、章节、随机练习、模拟题、错题和收藏冒烟测试。

正式数据导入和版本指针切换属于云端写操作。每次执行前都要明确展示目标环境、发布 ID、题量、当前版和将成为上一版的版本，并取得用户确认。

## 9. 回滚与清理

回滚只把 `question_bank_config/active` 的 `active_release_id` 切回 `previous_release_id`，然后互换两个版本的状态。回滚前后均核对题量并执行读取冒烟测试。

新版本稳定后，云端只保留：

- 当前正式版的题目。
- 上一个正式版的题目。
- 所有版本的轻量发布记录。

更早版本的题目文档先按 `release_id` 精确统计，再单独请求删除确认。删除失败不影响当前题库；禁止使用无版本条件的批量删除。

## 10. 权限与安全

- 三个集合的小程序客户端权限均为“无权限”。
- `questionBank` 云函数只读，不包含发布或删除分支。
- 发布操作通过已登录的微信云开发控制台完成；不要求用户提供 AppSecret、SecretId 或 SecretKey。
- 环境 ID 和 AppID 可以进入项目配置；任何令牌、密钥、OpenID 和本地登录缓存不得进入版本库或日志。
- 云函数对 action、版本 ID、筛选字段、数组长度和题目 ID 格式做白名单校验。
- 不把数据库错误详情传回客户端。
- 云资源创建、删除、套餐变更、自动续费和超额付费设置均需单独确认。

## 11. 测试方案

### 11.1 本地发布器

- 只有 `verified` 题目进入云发布包。
- 六个分片完整，数量与构建报告一致。
- `_id`、`release_id` 和 `question_id` 唯一且稳定。
- 内容摘要对相同输入可重复生成。
- 任一输入非法时不写出完整发布包。

### 11.2 云函数

- `manifest` 只返回当前正式版本。
- `list` 正确应用职业、等级、模块、章节和小节筛选。
- `getByIds` 去重、保持顺序并忽略不存在的 ID。
- 非法 action、过长数组和非法字段被拒绝。
- 数据库分页超过单次上限时仍返回完整结果。
- 数据库异常返回稳定业务错误，不泄露堆栈。

### 11.3 小程序

- 云环境初始化使用指定环境 ID。
- Repository 正确映射 `snake_case` 到 `camelCase`。
- 同一运行期间固定版本且不写题库缓存。
- 各入口显示加载、失败和重试状态。
- 练习开始前获得完整题目集合。
- 本地进度、错题和收藏逻辑保持原行为。

### 11.4 首次上线验收

- 本地完整验证通过。

- 数据库客户端直接读取被拒绝，云函数读取成功。

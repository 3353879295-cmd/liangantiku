# 保管员五等级题库章节分类设计

日期：2026-08-07

状态：用户已确认

## 背景与问题

保管员五等级导入题库共有 4110 道题：

| 等级 | 系统等级 | 题数 |
| --- | ---: | ---: |
| 初级 | 5 | 1130 |
| 中级 | 4 | 658 |
| 高级 | 3 | 950 |
| 技师 | 2 | 748 |
| 高级技师 | 1 | 624 |

当前导入器把所有题目统一写为：

- `module = 资料整理题库`
- `chapter_id = warehouse-import-c01`
- `section_id = warehouse-import-c01-s01`

因此小程序只能显示一个“保管员综合理论”章节。截图中技师等级显示的 748 题就是该等级全部题目，并非页面聚合错误。

原始 DOCX/PDF 题库主要按单选、多选、判断等题型组织，缺少可靠的知识章节标记，不能从文件结构直接恢复章节。分类必须根据权威目录、题目语义和可审计规则重新生成。

## 目标

1. 按教材目录和《（粮油）仓储管理员国家职业技能标准（2019 年版）》为五个等级建立稳定章节和小节。
2. 使用确定性、可测试、可重复执行的规则分类器重建 `chapter_id` 和 `section_id`。
3. 保留现有问题 ID、题干、选项、答案和来源信息，避免破坏已有答题记录。
4. 章节分类置信度不足的题目不进入正式发布分片，转入待复核文件。
5. 章节可信但小节无法细分的题目进入该章的“本章综合考查”小节，不跨章兜底。
6. 正式题库不得再引用 `warehouse-import-c01` 或 `warehouse-import-c01-s01`。

## 非目标

- 本轮不修改题干、选项、答案或解析内容。
- 本轮不重新判断题目等级；等级继续由来源文件确定。
- 本轮不处理粮油质量检验员题库。
- 本轮不自动发布云端版本；本地审计通过后再由用户确认发布。
- 本轮不调用外部大模型服务参与正式分类，避免不可重复和数据外发。

## 权威分类依据

分类依据按以下优先级使用：

1. 本地《（粮油）仓储管理员（初级/中级/高级）》教材目录，用于等级 5、4、3 的章节和小节。
2. 《（粮油）仓储管理员国家职业技能标准（2019 年版）》，职业编码 `4-02-06-01`，用于五等级职业功能，并补齐等级 2、1 的目录。
3. 现有 `data/knowledge_catalog.json` 中已稳定使用的等级 5、4、3 ID。

高级别覆盖低级别要求，因此职业道德、基础知识和法律法规目录适用于五个等级；等级专属章节按对应等级的职业功能设置。

## 分类器架构

分类逻辑从一次性文件解析器中拆分为独立模块：

- `src/grain_quiz/warehouse_classify.py`：文本规范化、规则评分、候选排序和分类结果。
- `tools/warehouse_classification_rules.json`：各等级章节和小节的正向词、强特征短语、排除词与权重。
- `tools/import_warehouse_sources.py`：继续负责读取和解析原始文件，调用分类器后才写正式 JSONL。

分类器接口：

```python
@dataclass(frozen=True)
class ClassificationCandidate:
    chapter_id: str
    section_id: str
    score: int
    matched_terms: tuple[str, ...]


@dataclass(frozen=True)
class ClassificationResult:
    status: Literal["section", "chapter", "pending"]
    chapter_id: str | None
    section_id: str | None
    candidates: tuple[ClassificationCandidate, ...]


def classify_warehouse_question(
    *,
    level: int,
    stem: str,
    options: Sequence[str],
    explanation: str,
) -> ClassificationResult:
    ...
```

## 规则结构与评分

分类输入由题干、选项和解析组成，权重分别为：

- 题干命中：基础权重乘以 3。
- 选项命中：基础权重乘以 1。
- 解析命中：基础权重乘以 2。

规则词分为：

- `strong_phrases`：完整专业短语，基础权重 4，例如“磷化氢环流熏蒸”“粮堆结露”“仓房气密性”。
- `keywords`：一般专业词，基础权重 2，例如“熏蒸”“害虫”“粮温”。
- `context_terms`：与其他词同时出现才计分，基础权重 1，例如“浓度”“通风”“方案”。
- `exclude_terms`：用于消除相邻章节误判，每次命中扣 4 分。

文本使用 NFKC 规范化、统一大小写并移除无意义空白，但不删除专业数字、单位和化学名称。

分类决策固定如下：

1. 小节第一名得分不少于 12，且领先第二名不少于 4 分：直接采用该小节，状态为 `section`。
2. 小节未达阈值，但章节汇总第一名不少于 9，且领先第二名不少于 3 分：采用该章的 `s00`，状态为 `chapter`。
3. 未满足以上条件、第一名并列、或等级不存在对应目录：状态为 `pending`，不得进入正式分片。
4. 基础目录规则与等级专属目录规则同时匹配时，只有基础目录领先至少 4 分才进入基础目录，否则优先等级专属职业功能。
5. 分类不得使用正确答案键本身作为特征，避免 A/B/C/D 分布影响结果。

同样输入和规则版本必须始终产生同样结果。

## 规则示例

```json
{
  "level": 2,
  "chapter_id": "warehouse-l2-c03",
  "section_id": "warehouse-l2-c03-s04",
  "strong_phrases": ["硫酰氟熏蒸", "储粮害虫防治方案"],
  "keywords": ["熏蒸剂", "杀虫剂", "害虫", "防护剂"],
  "context_terms": ["剂量", "浓度", "密闭", "散气"],
  "exclude_terms": ["害虫识别", "虫态检查"]
}
```

“害虫识别、虫态、检查、取样”偏向粮情检查；“药剂、剂量、熏蒸、防治、散气”偏向粮情控制。相邻类别必须通过排除词和组合词消除歧义，不能只依赖单个“害虫”关键词。

## 数据输出与审计

### 正式题库

分类状态为 `section` 或 `chapter` 的题目保留原 ID，并更新：

- `module`：目录章节标题。
- `topic`：目录小节标题。
- `chapter_id`、`section_id`：分类结果。
- `keywords`：保留原关键词，并追加命中的标准术语；去重后写回。
- `content_version`：增加 1，表示分类元数据发生变化。

### 待复核文件

`pending` 题目写入 `tmp/warehouse-classification-review.jsonl`，每条包含：

- 原问题 ID、等级、题干和来源文件。
- 前三名候选章节和小节。
- 每个候选的分数和命中词。
- `ambiguous`、`low_score` 或 `no_rule` 原因。

这些题目不写入 `data/questions/warehouse_l*.jsonl` 的正式发布结果。

### 分类审计文件

全部成功分类题目另写 `tmp/warehouse-classification-audit.jsonl`，保存最终路径、置信状态、得分和命中词，用于抽样复核，但不进入小程序包或云端题库。

## 数据流

```text
原始 DOCX/PDF
  -> 题目解析与去重
  -> 标准规则分类器
     -> section: 写入明确小节
     -> chapter: 写入该章 s00 综合考查
     -> pending: 写入待复核文件，不发布
  -> taxonomy/catalog 校验
  -> 五等级 JSONL
  -> dist/json 发布分片
  -> 小程序运行时数据或云端发布包
```

## 测试设计

### 分类器单元测试

每个新增技师和高级技师小节至少提供一个手工构造的代表性问题，断言：

- 命中正确章节和小节。
- 相邻类别不会仅因共享词误判。
- 并列候选进入 `pending`。
- 章节明确、小节模糊时进入对应 `s00`。
- 同一问题重复分类结果完全一致。

等级 5、4、3 至少覆盖出入库、粮情检查、粮情控制和共享基础知识的代表性问题。

### 数据集不变量测试

- 所有正式问题 ID 保持唯一。
- 正式问题中不存在 `warehouse-import-c01` 和 `warehouse-import-c01-s01`。
- 每个 `chapter_id`、`section_id` 都属于相应职业和等级目录。
- 正式问题的等级、ID 前缀、来源和答案结构保持不变。
- 分类前后相同 ID 的题干、选项和答案完全相同。
- 所有待复核问题均未进入正式分片。

### 发布链路测试

- 五个 warehouse 分片均可构建并同步。
- 小程序目录按等级只展示共享基础目录和当前等级目录。
- 章节题数之和等于当前等级正式发布题数。
- 章节练习和小节练习按更新后的稳定 ID 返回正确问题。
- 云端发布包与本地分片的等级、章节和小节分布一致。

## 验收标准

1. 五等级正式题库中不存在旧的统一占位章节 ID。
2. 五个等级页面均显示多个知识章节，不再把该等级全部题目放进一章。
3. 自动分类覆盖率不低于解析成功题目的 80%；低于 80% 时不发布，先补充规则。
4. 每等级按章节分层抽样 20 题，共 100 题；人工判断章节正确率不低于 90%。
5. 任一章节抽样正确率低于 85% 时，必须修正规则并重新生成全部题库。
6. 待复核数量、原因分布、章节分布和小节分布必须形成审计报告。
7. Python 全量测试、数据校验、构建、小程序同步和 `npm run verify` 全部通过。
8. 本地验证完成后停止，不自动覆盖现有云端活动版本；云端发布需要用户再次确认。

## 兼容与迁移

- 问题 ID 不变，因此进度仓库中按问题 ID 保存的答题、错题和收藏记录继续有效。
- 原占位章节 ID 只存在于旧发布版本；新版本不提供该 ID 的章节练习入口。
- 如果用户从旧页面返回，新目录会按当前活动发布重新加载；不存在的旧章节路由应返回无效参数提示，而不是回退到全部题目。
- 分类规则文件包含 `version` 字段。规则修改后必须重建全部五等级分片，禁止局部手工改 JSONL。

## 实施边界

实施应在独立分支和工作树中进行，避免覆盖当前 `cloud-warehouse-five-level-release` 工作树中的未提交云端接入改动。完成本地分类、审计和小程序验证后，再将结果合入云端发布工作树。

# 储粮保管员与粮油质检员刷题小程序设计规格

**状态：** 已确认

**日期：** 2026-07-22

**首发平台：** 微信小程序

**首版定位：** 可在微信开发者工具中直接运行的本地优先 MVP

## 1. 产品目标

建设一款面向储粮保管员和粮油质量检验员考证学习的微信小程序。产品采用类似成熟题库应用的清晰刷题流程，重点提供章节练习、模拟考试、即时解析、错题重练、收藏、学习统计和实操知识卡。

首版覆盖以下六个考试分类：

1. 储粮保管员（初级）
2. 储粮保管员（中级）
3. 储粮保管员（高级）
4. 粮油质量检验员（初级）
5. 粮油质量检验员（中级）
6. 粮油质量检验员（高级）

首版不依赖登录或后端服务。题库、答题记录、错题、收藏和学习统计在本地运行，同时通过统一数据访问接口为后续微信云开发预留接入点。

## 2. 用户与核心场景

主要用户是准备粮食行业职业技能考试的在职学习者。典型场景包括：

- 利用工作间隙完成 5～20 道章节或随机练习。
- 完成一套模拟考试并查看薄弱章节。
- 对错题进行集中复习，理解答案而非只记选项。
- 在现场工作或考前复习时查看标准操作步骤与安全提醒。
- 在无网络或网络不稳定的环境下继续学习。

## 3. 首版范围

### 3.1 核心页面

底部导航为“首页、题库、实操、我的”。七个核心页面为：

1. **首页：** 当前证书、今日目标、连续学习天数、累计答题量、正确率、继续练习、每日一练和错题重练入口。
2. **题库：** 证书与等级切换、章节练习、顺序练习、随机练习和模拟考试入口。
3. **答题：** 题干、选项、收藏、进度、提交、解析和上一题/下一题操作。
4. **答题卡：** 已答、未答、正确、错误状态，支持快速跳题和返回检查。
5. **练习报告：** 得分、正确率、用时、错题数、薄弱章节、错题解析和再次练习入口。
6. **实操：** 图文技能卡、操作步骤、安全提醒、常见错误和关联练习。
7. **我的：** 学习日历、累计题量、正确率趋势、目标设置、证书切换和本地数据管理。

错题本、收藏题和通用题目列表作为独立路由或上述页面的子视图呈现，不占用底部导航。

### 3.2 练习能力

- 支持单选题、多选题、判断题和案例题。
- 章节练习按知识章节筛选题目。
- 顺序练习按题库顺序加载。
- 随机练习使用可测试的无重复抽题逻辑。
- 模拟考试在交卷前不显示答案，交卷后统一生成练习报告。
- 普通练习提交后立即显示正确答案、题目解析、知识点和易错提示。
- 中途退出时保存会话，下次进入可继续。
- 答题卡支持定位题目；模拟考试允许修改未交卷答案。

### 3.3 错题、收藏与统计

- 答错后自动加入错题本，并累计错误次数。
- 错题可按岗位、等级和章节筛选。
- 错题重练答对后允许标记“已掌握”，但保留历史错误数据。
- 任意题目可以收藏或取消收藏。
- 统计累计答题量、正确题数、正确率、练习时长、连续学习天数和章节正确率。
- 首页和“我的”使用同一统计服务，避免口径不一致。

### 3.4 实操内容

首版至少提供 12 张实操技能卡，覆盖但不限于：

- 粮情检查
- 储粮通风
- 熏蒸作业安全
- 粮食出入库检查
- 样品扦取与缩分
- 水分检测
- 杂质检测
- 容重检测

每张技能卡包含适用岗位、操作目的、准备事项、分步操作、安全提醒、常见错误和关联练习。首版使用图标、流程编号和排版表达，不使用 AI 风格装饰插画。

### 3.5 示例内容

- 至少 48 道结构完整的示例题，六个分类各不少于 8 道。
- 每道题必须包含答案和解析；适用时同时包含知识点与易错提示。
- 示例题使用 `reviewStatus: sample` 标识，与后续审核通过的正式题库区分。
- 上线前由题库负责人将正式题目导入并完成内容审核。
- 提供标准 JSON 数据格式和 Excel 字段说明；首版不实现 Word/PDF 自动识别。

## 4. 明确不做的内容

首版不包含微信登录、云同步、管理后台、排行榜、社交、支付、视频托管、AI 出题、Word/PDF 自动识别、正式上线审核材料和暗色主题。

## 5. 视觉与交互设计

### 5.1 设计语言

视觉采用克制的 Apple 式浅色界面：

- 页面背景使用接近 `#F5F5F7` 的暖灰色。
- 主文字使用接近 `#1D1D1F` 的深灰色，辅助信息降低对比度。
- 强调色使用沉稳的储粮绿；红色仅表达错误或危险提示。
- 字体使用系统字体与苹方，不引入额外字体包。
- 使用 8pt 间距体系、细分隔线、适度圆角和极轻阴影。
- 避免大面积渐变、过多悬浮卡片、玻璃拟态、发光效果和装饰性动画。
- 图标保持统一、简洁和线性，不使用机器人、星光或通用 AI 插画。
- 文案直接、具体，不出现“AI 助学”“智能赋能”等空泛表述。

### 5.2 答题交互

- 题目是答题页的视觉主体，选项提供不小于 44px 的点击区域。
- 未提交时保持中性；提交后正确项使用储粮绿，错误选择使用克制的红色边框。
- 解析紧跟作答结果展示，不用弹窗打断普通练习。
- 模拟考试只记录答案，不提前暴露结果。
- 底部操作区适配 iPhone 安全区，关键操作保持单手可达。
- 动画只用于状态切换和轻量反馈，并尊重系统减少动态效果设置。

### 5.3 设计令牌

颜色、字号、行高、间距、圆角、阴影和层级统一定义在主题文件中。业务页面不得自行散落硬编码样式值；特殊值必须有明确语义命名。

## 6. 技术架构

### 6.1 技术路线

- 原生微信小程序
- TypeScript 严格模式
- TDesign MiniProgram 组件库
- 微信小程序原生 WXML/WXSS
- Vitest 测试纯业务逻辑
- ESLint、Prettier、Stylelint 进行静态检查

设计确认时核对到的工具版本为：TDesign MiniProgram 1.15.3、TypeScript 7.0.2、ESLint 10.7.0、Prettier 3.9.6、Stylelint 17.14.1、Vitest 4.1.10、miniprogram-api-typings 5.2.1。实施时固定精确版本并提交锁文件，不使用浮动依赖范围。

### 6.2 开源复用决策

- 使用 MIT 许可且仍在维护的 TDesign MiniProgram 作为通用组件基础。
- 不直接复制未声明许可证的 `kesixin/QuestionWechatApp` 业务代码。
- 不以 GPL-3.0 的 `mark420524/question` 为代码基础，避免引入不符合预期的分发约束。
- 可以借鉴公开产品的信息架构与通用交互模式，但视觉、业务代码和数据模型独立实现。

### 6.3 目录职责

```text
miniprogram/
  app.*                  小程序入口、全局主题与初始化
  pages/                 七个核心页面及错题/收藏等子页面
  components/            题目卡、选项、解析、进度和统计组件
  features/              按练习、错题、实操等业务聚合的模块
  services/              题库、记录、统计和会话服务
  repositories/          本地与未来云端数据访问实现
  stores/                当前练习与全局偏好状态
  data/                  内置题库、证书、章节和实操数据
  types/                 领域类型定义
  utils/                 纯函数工具
  styles/                主题令牌与共享样式
tests/                   与领域模块对应的单元测试
docs/                    运行、题库格式、代码规范和验收文档
```

每个模块只承担一个清晰职责。页面负责组合和交互，领域规则由服务与纯函数实现，持久化只由 Repository 与存储服务处理。

## 7. 数据模型

### 7.1 题目

题目包含以下稳定字段：

```ts
type QuestionType = 'single' | 'multiple' | 'boolean' | 'case';
type CertificateRole = 'keeper' | 'inspector';
type CertificateLevel = 'junior' | 'intermediate' | 'senior';

interface Question {
  id: string;
  role: CertificateRole;
  level: CertificateLevel;
  chapterId: string;
  type: QuestionType;
  stem: string;
  options: Array<{ id: string; text: string }>;
  correctOptionIds: string[];
  explanation: string;
  knowledgePoint: string;
  commonMistake?: string;
  difficulty: 1 | 2 | 3;
  source?: string;
  reviewStatus: 'sample' | 'verified';
}
```

多选答案按集合比较，选项顺序不影响判分。判断题也使用稳定选项 ID，避免对显示文案进行字符串判断。

### 7.2 学习与错题记录

学习记录保存题目 ID、用户答案、是否正确、用时和作答时间。错题记录额外保存首次错误时间、最近错误时间、错误次数、最近重练结果和掌握状态。收藏只保存题目 ID 与收藏时间。

### 7.3 练习会话

练习会话保存模式、筛选条件、题目 ID 列表、当前位置、答案映射、开始时间和考试提交状态。会话保存后不嵌入完整题目内容，避免重复数据与题库升级冲突。

### 7.4 实操技能卡

技能卡保存岗位、主题、目的、准备事项、步骤、安全提醒、常见错误和关联题目 ID。步骤使用结构化数组，页面不得解析自由格式 HTML。

## 8. 数据访问与状态流

页面通过 `QuestionRepository`、`ProgressRepository` 和 `SkillRepository` 获取数据，不直接读取 JSON 或调用 `wx.setStorageSync`。

```ts
interface QuestionRepository {
  list(filter: QuestionFilter): Promise<Question[]>;
  getByIds(ids: string[]): Promise<Question[]>;
  getById(id: string): Promise<Question | null>;
}
```

首版提供本地实现。云端占位实现保持相同接口，并明确返回“未配置”状态；不得静默请求不存在的云服务。

标准答题数据流为：

1. 页面提交练习条件。
2. 题库服务从 Repository 获取候选题目。
3. 组卷模块生成有序题目 ID 列表并建立会话。
4. 用户作答后评分模块返回正确性与解析展示状态。
5. 记录服务更新学习记录、错题和章节统计。
6. 页面订阅当前会话状态并更新视图。

## 9. 本地存储与迁移

- 所有键使用统一命名空间，禁止页面自建临时键。
- 根数据包含 `schemaVersion`。
- 初始化时校验数据结构并执行顺序迁移。
- 当前练习会话和长期学习记录分开存储。
- 清除学习数据必须二次确认，题库与应用配置不受影响。
- 存储失败时保留内存中的当前会话并给出明确提示。

## 10. 错误与空状态

- 无匹配题目时展示空状态，并提供修改筛选条件的入口。
- 题目数据无效时跳过该题、记录诊断信息，不让整个练习崩溃。
- 本地记录损坏时备份原始异常数据标记，重建可用结构并提示用户。
- 恢复会话时若部分题目已不存在，移除缺失题目并重新计算进度。
- 所有异常提示使用用户可理解的中文，不直接展示技术堆栈。

## 11. 代码规范

- TypeScript 开启严格检查，业务代码不得使用无说明的 `any`。
- 页面不得直接访问本地存储、内置 JSON 或未来云端 SDK。
- WXML、WXSS、TypeScript 和配置文件职责分离。
- 文件与目录使用 kebab-case；类型使用 PascalCase；变量与函数使用 camelCase；常量使用 UPPER_SNAKE_CASE。
- 组件属性、事件和数据结构必须有明确类型。
- 公共逻辑优先写为无副作用纯函数，方便测试。
- 单个文件出现多个职责时按领域拆分，不以任意行数机械拆分。
- 禁止未使用变量、隐式全局、魔法存储键和散落的颜色/间距值。
- 提交前统一执行类型检查、脚本检查、样式检查和测试。

## 12. 测试策略

采用测试驱动方式实现核心行为：

- 评分：单选、多选无序比较、判断和案例题。
- 组卷：筛选正确、无重复、题量边界和空题库。
- 错题：首次加入、错误次数累计、重练和掌握状态。
- 会话：中断保存、恢复、提交后不可修改和缺题恢复。
- 统计：累计量、正确率、章节聚合和连续学习天数。
- 存储：版本迁移、损坏数据恢复和清除范围。

页面与组件通过微信开发者工具完成关键流程冒烟验证，覆盖首页进入练习、即时解析、模拟考试、答题卡、练习报告、错题重练、收藏和中断恢复。

## 13. 验收标准

1. 使用微信开发者工具导入项目后可直接运行，无需配置后端。
2. 六个考试分类都可进入并完成至少一组练习。
3. 四种题型能够正确作答与评分。
4. 普通练习答错后立即显示正确答案、解析、知识点和易错提示。
5. 错题自动进入错题本，并可完成筛选、重练和掌握标记。
6. 模拟考试交卷前不显示答案，交卷后生成练习报告。
7. 关闭并重新打开小程序后，学习记录和未完成会话仍然存在。
8. 实操页面至少展示 12 张结构完整的技能卡及关联练习。
9. 视觉符合已确认的简洁 Apple 风格，不出现明显 AI 模板化装饰或文案。
10. TypeScript、ESLint、Stylelint 和全部自动化测试均通过。
11. 项目包含运行说明、代码规范、题库 JSON 格式和 Excel 字段说明。

## 14. 后续演进

后续接入微信云开发时，在不修改页面调用方式的前提下增加云端 Repository、用户身份和同步策略。题库管理后台、Excel 自动导入、正式题库审核流、视频内容和上线合规材料均作为独立版本规划，不纳入本次 MVP。
## 15. 题库运行时集成说明

后续建立的题库流水线是小程序运行时题目的唯一生产者：审核通过的 JSONL 题目经 `grain-quiz build` 发布为六个 JSON 分片，再由 `miniapp/scripts/sync-question-bank.mjs` 校验并同步到小程序包内。页面只通过 `QuestionRepository` 读取同步结果，不绕过发布门槛直接加载编写中的题目。

## 本地实现

- 实际云函数入口改用个人虚拟支付道具直购；金额固定 2800 分、数量 1、六个自然月、不自动续费，协议 `env=0`。会员权益、额度与授权核心保留。
- `wx.login` code 仅交给会员函数，服务端 `code2Session` 匹配可信 SDK OPENID 后计算双签名，不存储或返回会话密钥。客户端验证云端商品金额/订单号，原样传递 signData 给 `wx.requestVirtualPayment`。
- 开发版会员请求显式连接 staging；体验版/正式版会员环境尚未开放。原全局 `cloud1-d2gglad830c91db10` 及 accountSync 配置保持不变。
- 明确取消/平台要求换单时使用新订单；未知支付结果只查旧单，不再次发起购买。退款状态为 REFUNDED，不按支付成功展示。
- 新购开关与已有订单处理解耦：缺失消息推送凭据时不开放新购，但具备有效支付凭据时仍可查旧订单。
- HTTPS 消息入口实现安全模式签名和 AES 解密、AppID 检查、严格 XML/JSON 解析及原始/Base64 报文边界。退款只能由已验签且被冻结的通知对象生成可信证明，不接受同形复制对象。完整退款保留支付锁和延期历史，标记退款后重放其他付款，晚到的支付通知不能恢复已退款权益。
- 原 timer 的运行时来源、Type、固定 TriggerName 三项守卫保持；没有恢复“OPENID 必须为空”。虚拟订单批量上限调整为两单，为查单与确认发货两次网络请求留出函数时间预算。PAID 订单确认发货失败仍可补偿，不重复延期。
- SDK 及锁文件未改，原 6 项传递告警仍未解决；没有使用强制审计修复，也没有添加支付或 XML 依赖。

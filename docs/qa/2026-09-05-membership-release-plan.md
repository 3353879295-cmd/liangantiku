### 接续核对：支付能力阻碍（2026-09-05）

本节为最新支付适用性结论，优先于下文尚以普通 JSAPI 为前提的商户配置和真实支付步骤；历史验收证据保留。

- 已直接读取[微信官方虚拟支付指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)：小程序内虚拟商品（含解锁功能、付费功能）购买和支付均须接入小程序虚拟支付，适用于 Android、iOS、鸿蒙、Windows 等终端。根据当前商品“28 元开通六个自然月、解除随机练习次数限制”的定义，判断其属于该范围。因此当前普通 JSAPI 入口不能直接用于此会员商品上线，不能仅以商户号绑定成功作为放行依据。
- 现有客户端调用 `wx.requestPayment`，服务端调用 `/v3/pay/transactions/jsapi`，通知处理为 API v3 `Wechatpay-*` 验签与 AES-GCM 解密。官方虚拟支付使用 `wx.requestVirtualPayment`、`/xpay/query_order` 和发货推送等不同协议；不能只替换前端 API 名称或复用现有回调配置就视为适配完成。
- 暂停为当前 JSAPI 商品入口配置真实商户密钥、创建公网回调路由或启用支付；继续保留支付关闭状态。先确认主体类型及公众平台“虚拟支付”开通状态，再明确支付适配范围。保留既有会员权益、额度、授权、订单幂等及通知乱序处理，不重开发会员系统或重构刷题。
- 普通商户号办理和 AppID 绑定状态已再次询问，尚待用户答复；同时待确认小程序主体、虚拟支付开通状态及目标终端。只收集办理状态，不索取聊天中的密钥。普通 JSAPI 权限与绑定核对入口见[官方权限指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791895)和[AppID 绑定说明](https://pay.wechatpay.cn/doc/v3/merchant/4013287504)。
- [个人主体官方指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment/person.html)另有开通条件：个人主体持居民身份证、服务类目含“工具”、完成认证及备案。企业/事业单位/个体工商户按企业指引核对。不能在主体未知时假定必须先申请普通商户号，也不能为满足条件填写与实际业务不符的类目。
- iOS 须按官方指引检查小程序简称、客户端版本和用户设备条件；Apple 支付不支持沙箱。本文原“独立 staging 不等于支付沙箱”边界继续适用。真实支付仍须先明确金额、次数和操作并取得确认。
- 后续固定 HTTPS 路径须在选定协议后落实。现有原始字符串/Base64 与 `Wechatpay-*` 头透传检查仅属于普通 JSAPI 回调契约，不能证明虚拟支付消息推送已经接入；本轮没有公网透传验收结果。

| 检查       | 操作与预期证据                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境隔离   | 核对函数所属环境和小程序测试调用目标；不要为测试会员而直接切换账号同步全局环境                                                                                       |

| 失败回滚   | 在独立测试夹具中模拟事务中途失败，核对额度、授权、订单、权益、交易锁不会部分提交；不破坏正常集合权限来制造失败                                                       |

## 第二阶段：真实支付与页面验收

前置条件：第一阶段通过、依赖风险有明确处理结论、公众平台确认商品支付能力、商户参数有效，并已确认具体测试用户、28 元金额和执行次数。不把真实密钥复制到本地 `.env`。

- 先一笔下单、取消、重付，核对商户单号与权益；前端返回成功但服务器未确认时不能开通。
- 验证回调先到/后到、断网后恢复、手动查单与定时补偿、重复通知，均只开通一次。乱序和月底等边界优先使用合成交易，避免为了测试而多次扣款。
- 核对五集合状态一致、六个自然月延期正确、到期后恢复免费限制。已经付款的订单若有异常，依据商户平台核对，不手工延长权益。
- 开发者工具与真机查看首页、随机设置、练习恢复、购买页、个人中心、报告再练一次；同时验收章节、错题、收藏、解析和交卷回看。
- 用户刚进入小程序时不得强制弹购买；支付未配置时应显示可理解状态。

## 发布与回退

只有云端与真机验收通过后才发布前端限制入口。回退前端时保留五个会员集合及支付处理能力，不删除订单/权益/交易锁。

当前 `MEMBERSHIP_PAYMENT_ENABLED` 同时影响下单、回调和补偿。已有待确认付款时，不能把关闭这个变量当作无损的“只暂停新购”：必须先核对待处理订单，保持能查单/验签的配置并制定对应处置，再执行变更。
